# gnaroshi-content-feed

Public generated content projection consumed by `Gnaroshi/gnaroshi.github.io`.

**Status:** Active generated-only interface between private source repositories and the public website.

This repository contains generated publishable output only. Canonical paper research and writing remain in private repositories and must never be copied here directly.

`manifest.json` records the Paper Lab and Writing source commit SHAs, content hash, generator, counts, and projection timestamp. Every update must be generated by `gnaroshi-studio`, pass its privacy and deterministic-output validation, and be committed as one feed transaction.

Do not edit blog, paper, data, asset, or manifest output manually. Imported seed, demo, draft, hidden, private-note, transcript, and local-path data are forbidden from this public repository.

## Dependency Boundary

Upstream input is read by the private `Gnaroshi/gnaroshi-studio` publisher from `gnaroshi-paper-lab` and `gnaroshi-writing`. Downstream, `Gnaroshi/gnaroshi.github.io` consumes this repository read-only. This repository must not contain canonical authoring files, private evidence, API code, or website components.

## Contract

Schema version 1 is defined in `schemas/index.json` and `schemas/v1/`. The bundled validator is the executable contract used by this repository, Studio, and the website:

```bash
npm ci
npm test
npm run feed:validate
```

`npm test` rebuilds deterministic valid and invalid fixtures. `feed:validate` checks schemas, relationships, locale pairing, aliases, manifest counts and hashes, graph integrity, declared assets, and privacy patterns.

The manifest has three explicit states:

- `bootstrap-empty`: every count is zero, `contentStage` is `seed`, eligibility is false, and derived snapshots are `null`.
- `generated`: publishable records were projected by Studio and source commit metadata is present.
- `invalid`: reserved for diagnostics and never accepted for deployment.

Missing evidence stays absent. Generators and consumers must not create placeholder reviews, reading sessions, translations, graph edges, formulas, or metrics.

Public blog records declare `category` as `research-note`, `implementation-note`, `paper-note`, `build-note`, or `essay`. Only the first three categories may contribute to research output metrics. Build notes must remain excluded from metric, graph, and weekly-review evidence.

## Assets

Every public asset must be declared in `assets/index.json`, use `/assets/<sha256>/<filename>`, match its declared SHA-256 and byte size, and use a supported media type. Raster dimensions are verified. SVG is rejected unless it passes the validator's sanitizer.

## Fixtures

`fixtures/` covers empty bootstrap output, English-only and Korean-only writing, complete and partial translation pairs, renamed slugs and aliases, paper sessions, simple/rich reviews, implementations, graph integrity, manifest drift, privacy leaks, and unhashed assets. These records are contract tests only and are never public activity.
